# 条理 · 借款人意外险条款语义工作台

按《借款人意外险语义树前端开发方案》实现的首个可运行版本。使用人保财险2022版条款与 `insurance_semantic_graph/fusion-1.0` 原始融合图，面向桌面演示与条款核对。开发方案、条款原文和语义树等源材料统一存放在 [materials](./materials/) 目录。

## 启动

已检测并复用 `D:\Node` 的 Node.js 24。本项目依赖已安装，可直接双击本目录 `start.cmd`，然后访问 http://127.0.0.1:5173/ 。关闭命令窗口或按 Ctrl+C 停止。

也可在本目录执行：

```powershell
.\start.ps1
```

`start.ps1` 会先检查 Node.js 和项目依赖；已存在则复用，缺少依赖才执行 `npm ci`。依赖位于 `node_modules`，npm缓存位于 `.cache/npm`，临时文件位于 `.cache/tmp`，均在项目所在的非C盘。脚本不会安装全局工具，不会下载 Node.js 或浏览器。若整个项目被移到C盘，脚本会停止。依赖版本由 `package-lock.json` 锁定；网络不可用时，已有依赖仍可直接启动。

如果手动运行 `npm install`，项目 `.npmrc` 也已将缓存固定到当前目录的 `.cache/npm`。建议使用启动脚本，以便同时设置临时文件目录。支持 Node.js 22.12+ / 24+。

## 已实现

- **条款、图、详情联动**：4个阶段总览；53个真实节点与120条流程出口；局部流程与全图；按ID及关键词搜索；51处来源摘录与原文上下文定位；原文反查多个节点；8项待核事项。
- **原图求值**：纯函数 `evaluate(graph, caseInput)` 从原始入口解释流程；支持三值逻辑、争议复核、实际读取顺序、带证据的事实、效果累积、Decimal十进制金额和计算前置校验。
- **计算依赖**：历史给付、时点保额、共享上限分别解析。历史账本校验作用域、截止时间、快照完整性、币种及付款唯一编号；重复的同一条导出记录只计一次，冲突记录进入复核。读取历史伤残付款不会执行当前伤残责任流程。
- **案例验证**：16个合成案例；五种结果码；身故与伤残完整路径；已付20万元／账本未知／明确0元；宣告死亡与生还返还；逐步轨迹、左右键导航、单字段试算、两例出口与金额差异定位。
- **评估与交付**：原始文件SHA-256、结构与定位校验、开发回归、节点/分支覆盖、未访问清单，界面与命令行均可导出详细报告。支持窄屏切换目录、图与详情。

条款目录默认收起为九个章节，逐级展开到条款、原文段落或编号分项。搜索时自动显示匹配项的祖先，点击叶子定位原文。“完整语义树”与各阶段子树均从左向右排列。阶段名称标在入口卡片上，点击可进入子树，返回时恢复原来的看图位置。首次进入完整图从左侧入口开始阅读，“适应全图”用于看整体，右下角缩略图可点击跳转。

正常给付和返还结果直接接在流程末端。补材料、复核等停止结果收在节点底部的出口标签里；点击单个标签或工具栏“本节点出口”可在节点附近展开，也可按节点 ID 检索。案例命中的停止结果沿实际路径显示。案例经过的连线、箭头和节点外圈使用蓝色，金额计算节点保留橙色标签。“查看计算来源”仅展开当前节点引用的数据和规则。

首屏使用单行顶栏，默认显示责任总览并收起右侧依据栏。点击具体节点后，右侧自动展开。左右栏可分别收起，“放大画布”可同时收起两侧栏，退出时恢复原来的分区、缩放和看图位置。“完整语义树”切换展示范围，“适应全图”调整缩放。建议切换“验证案例”，依次选择“普通意外身故”“已付伤残金20万元”“账本完整性未知”，再点击轨迹中的“意外身故保险金”，核对责任效果、扣减明细与2.1.1原文。右侧“条款依据”与页脚“查看条款”均可定位原文。

## 导入其他语义树

点击页面顶部「导入语义树」，选择使用 `insurance_semantic_graph/1.0` 或 `insurance_semantic_graph/fusion-1.0` 结构的 JSON。工作台按 JSON 的原文 SHA-256 查找内置或此前导入的原文。找不到匹配文件时，点击「选择条款原文」，补选对应的 UTF-8 Markdown 文件。原文通过行号和摘录检查后打开新树；JSON 未声明原文哈希时，报告会注明版本未由哈希确认。

内置、导入和刷新恢复的语义树使用相同的展示逻辑。系统根据 `responsibilities` 和实际流程生成阶段与责任总览，节点详情展示引用规则、计算表达式、依赖和原文依据。顶部下拉框只显示条款名称，宽度固定、超长名称以省略号截断；点击展开后可查看完整名称及对应的条款原文 MD 与语义树 JSON 文件名。导入的 JSON 和 MD 保存在当前浏览器的站点数据中，刷新后可重新选择，默认文件仍在 `materials`。验证案例随默认树提供。文件哈希校验需要通过本机地址或 HTTPS 打开工作台。

可在 JSON 中提供可选的 `view_config`。其中 `stages` 是由 `id`、`title`、`node_ids` 组成的有序列表，各流程节点应恰好归入一个阶段，终点可通过流程出口查看。`branch_labels` 按节点 ID 和分支键指定文案。未提供这些字段时，工作台自动生成相应视图。

## 验证与构建

```powershell
npm run validate   # 结构、引用、循环、可达性、51处原文定位与摘要
npm test           # 求值、边界、账本、效果保留与篡改回归测试
npm run report     # reports/regression.json，完整轨迹与未覆盖清单
npm run build      # 校验 + TypeScript + 静态构建到dist
.\start.ps1 -Preview  # 预览已有静态产物，端口4173
```

`release/insurance-web-v0.1.0.zip` 是可静态部署的页面包。将压缩包内容放在静态服务器根目录即可；不依赖后端服务。请通过HTTP访问，浏览器通常不能通过双击 `dist/index.html` 加载模块。项目已设置相对资源路径，可放在子路径部署。页面使用本地系统字体，无需远程字体或图片。ELK布局库按需加载。

浏览器验证脚本 `node scripts/browser-qa.mjs` 会复用本机已安装的Edge和运行环境已有的Playwright，自己临时启动静态预览，并在结束时关闭。不会下载安装浏览器。换机器时可用 `INSURANCE_BROWSER` 和 `PLAYWRIGHT_MODULE` 指定现有可执行文件/模块路径；找不到则直接报错。每次运行在 `.cache/tmp` 创建独立浏览器配置，截图与结果在 `test-results`。脚本中的现有工具默认路径来自本机环境，测试工具缺失不影响启动应用。

## 结果边界与后续验收

16个案例的预期来自方案条款和人工编写的设计预期表，全部标为**待业务审核**。开发回归通过数不能视作业务审核一致率或真实理赔准确率。目前业务审核例数为0；日期期间、鉴定比例、责任保额、账本完整性与保障有效性均由带状态的合成输入提供，不从自由文本或两个日期自动推断。

结构化事实编辑后，界面从入口重算并标为“自定义试算”；未改动的示例可用于核对设计预期。案例编辑只保存在当前页面内存，刷新后恢复，不写回原始数据。责任已通过但金额资料缺少时保留责任效果，金额为 `null`；明确零金额为字符串 `"0"`。金额已核定但受领人或保费条件未满足时，保留金额并分别展示待履行事项。

本次交付包含方案首版的主要浏览和执行能力；正式业务验收仍需审核者确认16个案例预期并完成宣告死亡分流、伤残汇合点、D04原文与差异定位的实际操作。回归报告明确列出未覆盖的12个结果节点及分支；后续应补测全部免责子条件组合、受益人失权、缺材料的各停止出口、递减保额及特殊记账口径。节点“已访问”不代表全部条件组合已经覆盖。多人账户、在线规则修改、真实理赔接口和多险种管理仍属后续范围。

## 代码结构

```text
src/data/       类型、原始数据导入、来源索引、真实边、阶段分组与校验
src/engine/     独立求值器、依赖解析与轨迹记录
src/cases/      合成输入、设计预期与结果对照
src/views/      React Flow画布、ELK布局与图标
src/App.tsx     条款、案例、步骤、节点详情与报告工作台
scripts/        构建前校验、覆盖报告与本机浏览器检查
tests/          核心执行与结构回归
reports/        可复现的完整设计回归报告
test-results/   本机浏览器检查结果与截图（不纳入源代码提交）
dist/           静态页面产物
```

新增案例时请明确列出已确认事实与证据，缺项保留未知，不默认填零或否。`review_status` 只有在业务审核实际完成后才能改为 `reviewed`。求值器只接收图与案例输入，不读取案例预期。

依照方案核对过的实现参考：[React Flow 多端口布局](https://reactflow.dev/examples/layout/elkjs-multiple-handles)、[elkjs](https://github.com/kieler/elkjs)、[Vite](https://vite.dev/guide/)。
